# ADR-003：Checkpoint、租约、幂等和恢复

状态：已采纳
日期：2026-10-06

## Context

工作流包含人工中断、页面刷新、重新进入、长耗时 LLM 调用和业务写库。
仅依靠内存状态会出现：

- 进程重启后无法继续；
- 同一会话被多个 worker 同时写入；
- 恢复节点重跑导致重复执行副作用；
- checkpoint 与业务库状态不一致。

## Decision

组合使用以下机制：

- 文件级 SqliteSaver 保存工作流 checkpoint；
- `thread_id` 作为会话恢复身份；
- 数据库会话租约串行化同一会话的写操作，并支持续租；
- 副作用后置到老师审批之后；
- AnswerRecord、TeacherDecision 和画像写入使用逻辑或数据库唯一约束保证幂等；
- H3 相关业务写入放入事务，失败整体回滚；
- 用 badcase 和回归测试覆盖恢复、重复点击和中断路径。

## Consequences

优点：

- 中断和重试成为可测试的工程路径；
- 恢复后不容易重复写画像或作答；
- 能明确解释“幂等”“租约”和“副作用后置”的必要性。

代价：

- checkpoint 与业务库没有跨库 exactly-once；
- 需要额外维护 migration、租约 TTL 和恢复测试；
- 状态机实现比简单同步函数更复杂。
