# ADR-002：程序判分与 LLM 归因分离

状态：已采纳
日期：2026-10-06

## Context

LLM 输出存在不确定性，不能作为数学题最终对错的权威来源。错误原因解释
适合使用自然语言模型，但结论必须和答案事实分开。

如果让 LLM 同时判对错和解释错因：

- 幻觉可能污染得分和画像；
- 同一答案的结果可能不稳定；
- 无法清晰判断错误来自模型、解析器还是题目本身。

## Decision

将职责拆成三层：

1. 程序负责事实：答案、有效根、过程断点和逐空判定；
2. LLM 只输出归因建议、证据和置信信息；
3. 老师负责最终确认、修正或推翻。

具体约束：

- `AttributionOutput` 不包含 `is_correct`；
- LLM 超时、异常或结构化输出失败时降级为 `evidence_source=program`；
- 没有学生步骤时不能编造错因；
- 老师确认前，画像更新不生效。

## Consequences

优点：

- 对错可复现，归因可替换；
- 模型失败不会破坏程序判分事实；
- 可以分别为程序判分和 LLM 归因设计测试与指标。

代价：

- 需要实现和维护程序求解器与数据契约；
- 归因质量不能由“非空率”证明，仍需人工审核和案例研究；
- 流程比单次 LLM 调用更复杂。
